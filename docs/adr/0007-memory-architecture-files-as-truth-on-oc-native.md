# Memory is files-as-truth on OpenClaw's native memory; the template provides shape, OC owns runtime

OpenClaw 2026.5.22 ships a native memory architecture (`MEMORY.md` + `memory/YYYY-MM-DD.md` + optional `DREAMS.md`, indexed by `memory-core` SQLite with FTS5 + sqlite-vec, with `memory_search` / `memory_get` tools, dreaming-based promotion, and bootstrap auto-load). The template adopts that architecture as the substrate and collapses the `domain-memory` plugin from a parallel storage system into a thin policy + aggregation layer on top. Source of truth is the markdown files in the workspace; the SQLite index is a regenerable derivative. The template seeds `MEMORY.md` and writes domain conventions; OpenClaw owns the file at runtime (bootstrap injection, dreaming promotion, compaction flush). The seed-then-OC-owns posture extends to the whole `domain/` tree.

## Considered Options

- **Keep our parallel SQLite store (status quo).** Rejected. `domain/openclaw/plugins/domain-memory/index.ts` reinvents what OC now ships natively — observations + chunks + FTS5 + sqlite-vec — and does so less well: hardcoded Ollama and 768-dim embeddings (OC autodetects providers and respects model dims), no promotion mechanism (OC has dreaming with score gates), no compaction flush (OC ships a silent memory-flush turn), and three of the original eight tables (`scratchpad`, `deferred_tasks`, `goals`) were never wired with write paths. Maintaining a second storage system would require building dreaming, multi-provider embeddings, and compaction flush ourselves.
- **Pure-markdown memory, drop semantic recall entirely.** Rejected. Semantic recall over accumulated observation history is the one capability markdown + grep cannot give us. The user can point at concrete future moments where vector search will surface what keyword search misses, even if no past moment proves it.
- **External DB (Supabase / Postgres + pgvector / Chroma / Qdrant).** Rejected. Supabase Cloud breaks data sovereignty; self-hosted Supabase is heavier ops than the entire rest of the template. Separate-process vector stores (Chroma/Qdrant) break the lightweight + portable contract that lets a worker `tar` their workspace and walk away with everything. None of these earn their footprint for a single-worker domain agent.
- **LanceDB (already named as a future substrate in BLUEPRINT.md).** Considered. OC ships `memory-lancedb` as a plugin alternative. Not adopted now because `memory-core` (SQLite + sqlite-vec) already satisfies the substrate need with zero ops; LanceDB becomes interesting only if we hit recall-quality or scale limits that `memory-core` cannot meet. Track as a future swap, not a current adoption.
- **DB-as-truth with files as a human-readable overlay.** Rejected after explicit grilling. Files-as-truth honors data sovereignty in the strongest way (the workspace is a folder; the agent dies tomorrow and everything is still readable in any editor), gives natural Obsidian-vault composition, and makes the index disposable so substrate swaps are migration-free.
- **Fight OC for `MEMORY.md` ownership (ADR 0004 status quo).** Rejected. ADR 0004 was written before OC native memory shipped. OC now reads `MEMORY.md` at session start, the dreaming sweep appends to it, and `openclaw memory promote --apply` writes to it. Owning the file would require reimplementing bootstrap injection and disabling dreaming/promotion — losing capabilities we don't have ourselves and would have to build. The spirit of ADR 0004 ("template doesn't write to OC bootstrap surfaces") still holds; `MEMORY.md` is now an OC bootstrap surface and the rule extends to it.
- **Per-project memory subfolders (`memory/<slug>/YYYY-MM-DD.md` or `projects/<slug>/memory/`).** Rejected. OC's bootstrap auto-load looks for flat files at the root of `memory/` matching `YYYY-MM-DD.md` or `YYYY-MM-DD-<slug>.md`. Nested project subtrees stay searchable via `memory_search`, but they lose the bootstrap auto-load benefit — the most valuable thing OC's memory gives for free. Per-project subfolders give cleaner file listings at the cost of capabilities we want to keep.
- **Flat tree + frontmatter project scoping.** Accepted. Filename pattern `memory/YYYY-MM-DD-<topic>.md` (where `<topic>` is a project slug or domain-level topic); frontmatter carries `project: <slug>` or `project: domain`. Filter at query time via `domain_memory_query` wrapper. Preserves bootstrap auto-load across all projects; cross-project recall works without per-project `extraPaths` maintenance.
- **Inbox folded into `memory/`.** Rejected. The whole `memory/` tree is indexed and the today+yesterday daily notes auto-load into the bootstrap prompt — raw transcripts and clipped articles would dominate retrieval and eat bootstrap budget. Inbox stays as a staging zone *outside* the recall index; distillation produces a curated `memory/YYYY-MM-DD-<topic>.md` with `source: inbox` frontmatter. ADR 0002's principle (human gates the boundary) is preserved; the implementation specifics change because the destination changed.
- **Keep `scratchpad` / `deferred_tasks` / `goals` tables, wire them properly.** Rejected. OC primitives now cover all three: `scratchpad` → a single `memory/scratchpad.md` markdown file with checkbox items; `deferred_tasks` → OC commitments (inferred, channel-scoped, heartbeat-delivered); `goals` → OC scheduled tasks (cron) + heartbeat rows. Two parallel schedulers is worse than one; a single markdown file is simpler than a SQL table for an open-tasks list nobody indexed anyway.

## Consequences

- **The `domain-memory` plugin collapses from 8 tools to 3.** Survivors: `domain_memory_query` (wraps OC's `memory_search` with bounded snippets, redaction defense-in-depth, project filter, and a synthesis hint); `list_active_projects` (filesystem walk over `memory/` reading frontmatter `project:` and `ts:`); `domain_status` (filesystem walk for kind counts, scratchpad open count, project activity). Deleted: `domain_info`, `scratchpad_list`, `observation_write`, `memory_maintenance`, `raw_observations`. Plugin loses `better-sqlite3`, `sqlite-vec`, and the Ollama embedding code — those concerns move to OC's `memory-core`.
- **Seed-then-OC-owns extends across `domain/`.** Everything under `domain/` is treated as an installer seed: `MEMORY.md`, `AGENTS.md`, `HEARTBEAT.md` (where applicable per ADR 0004), context files. After install, OC and the agent own the workspace; the template does not write back. `domain/MEMORY.md` keeps its current location with a clarifying header comment; no `domain/seeds/` folder is created (a one-off classification for one file would not fix the broader collision).
- **Inbox stays where it is, with a sharper role.** `base/inbox/` and `domain/inbox/` are unchanged. The `_inbox/` → `_processed/` archival lifecycle continues. Distillation now lands at `memory/YYYY-MM-DD-<topic>.md` (OC's slugged daily-note variant) with provenance frontmatter (`source: inbox`, `from: <raw-filename>`). The inbox itself is never added to OC's `memorySearch.extraPaths` — pre-distillation content must not enter the recall index.
- **Project scoping is data, not structure.** Frontmatter `project: <slug>` is the canonical scope. `domain_memory_query` filters at query time. Per-project durable knowledge (architecture, decisions specific to one project) continues to live in `projects/<slug>/context/*.md` (template-owned per ADR 0004); per-project lightweight observations live in flat `memory/YYYY-MM-DD-<slug>.md`. Memory daily notes are the observation stream; project context files are the durable per-project knowledge.
- **Dead tables and their tools are deleted entirely.** `scratchpad` → `memory/scratchpad.md` (a single checkbox-list file the agent appends to). `deferred_tasks` → OC commitments. `goals` → OC scheduled tasks + heartbeat rows. No migration is needed because no production data ever existed.
- **`memory-wiki` adoption is gated on validation, not assumed.** OC's `memory-wiki` plugin (a compiled knowledge layer with structured claims, dashboards, contradiction tracking, Obsidian render mode) is a strong candidate for the durable knowledge surface but commits us to 5 new tools, a new vault, and a compile pipeline. Adoption requires six binary checks first: (1) Obsidian render mode produces files our obsidian skills can read; (2) `privacyTier` is enforced, not just labelled; (3) compile pipeline is local-only with no network calls; (4) bridge mode works with our Ollama-only `memory-core`; (5) `wiki_lint` catches contradictions/missing-evidence/low-confidence as advertised; (6) structured-claims authoring feels natural over 5-10 real entries (proxy for whether the schema gets used or rots). The full checklist and decision tree live in [`docs/agents/memory-wiki-validation.md`](../agents/memory-wiki-validation.md). Validation is captured as a tracked task; not blocking this ADR.
- **CONTEXT.md gains memory terms.** *OC native memory*, *slugged daily note*, *dreaming / promotion*, *memory seed*, *recall defense-in-depth*. The previous `Memory DB` term is removed from the working glossary because the template no longer owns a memory DB.
- **DOCK.md updates.** The plugin-tool allowlist drops the five deleted tools. The "Memory DB: local only" line is replaced with "Memory index: owned by OpenClaw's `memory-core`; the underlying SQLite store is regenerable from the markdown files in the workspace."
- **`install.sh` changes.** Stops shelling out an Ollama-specific embedding default to the plugin (that concern is now ADR 0008). Drops the plugin's env-var rewrites for `DOMAIN_MEMORY_DB_PATH` / `DOMAIN_MEMORY_PATH` (the plugin no longer owns a DB). Continues to copy `domain/MEMORY.md` into the workspace as a seed.
- **Routing rows referencing the deleted tools are updated.** `domain/AGENTS.md` Distill, Session start, Heartbeat, and Session end rows now load skills that call `memory_search` / `memory_get` directly (with the wrapper `domain_memory_query` for redacted recall when needed). The agent writes daily notes by writing markdown files, not by calling `observation_write`.
- **Substrate swaps are migration-free.** Because the markdown files are the source of truth, swapping `memory-core` for `memory-qmd`, `memory-honcho`, or `memory-lancedb` is a config change. The files don't move; only the index implementation does. This is the durable benefit of files-as-truth.
